Engenharia de Dados: Spec de Integração (Gupy para AWS S3)1. Objetivo do ProgramaAutomatizar a extração de dados de vagas/candidatos do portal Gupy e realizar a ingestão desses dados brutos em um bucket da Amazon Web Services (AWS S3). O processo deve rodar de forma agendada (ex: diariamente) seguindo o conceito de Data Lake Architecture (camada Raw/Bronze).2. Arquitetura e Fluxo de DadosO fluxo do programa deve seguir rigorosamente as quatro etapas abaixo:[ Gupy API / Scraping ] ➔ [ Tratamento Inicial (Memória) ] ➔ [ Autenticação AWS ] ➔ [ Upload S3 (.json/.parquet) ]
Detalhes das Etapas:Extração: Conectar à API da Gupy (ou via automação web/scraping se a conta não tiver acesso à API oficial) utilizando credenciais seguras.Transformação: Validar se o payload recebido é um JSON válido e adicionar metadados de controle (extracted_at).Persistência Local (Opcional/Temporária): Salvar em um diretório /tmp ou processar diretamente em memória usando buffers (io.BytesIO) para evitar lixo no disco.Carga: Enviar o arquivo para o S3 utilizando a biblioteca boto3.3. Requisitos Técnicos3.1. Tecnologias ObrigatóriasLinguagem: Python 3.10+Requisições: requests (para API oficial) ou playwright/selenium (se houver necessidade de scraping).SDK AWS: boto3 (versão mais recente).Variáveis de Ambiente: python-dotenv (nunca chumbar credenciais no código).3.2. Estrutura de Destino no S3 (Particionamento)Para garantir a performance de futuras consultas (via Athena, por exemplo), os arquivos devem ser gravados seguindo a estrutura de partição por data:s3://[NOME_DO_BUCKET]/raw/gupy/[TIPO_DE_DADO]/year=YYYY/month=MM/day=DD/Exemplo de arquivo: s3://meu-bucket-dados/raw/gupy/vagas/year=2026/month=05/day=22/vagas_143200.json4. Tratamento de Erros e ResiliênciaO script deve ser resiliente e não quebrar por instabilidades comuns de rede.Rate Limit (Gupy): Implementar Exponential Backoff (tentativas espaçadas) caso a Gupy retorne erro 429 (Too Many Requests).Falha de Conexão: O programa deve tentar retransmitir o request até 3 vezes antes de falhar e alertar.Logs: Implementar o módulo logging do Python para registrar:INFO: Início do processo, quantidade de registros encontrados, sucesso no upload.WARNING: Tentativas de reenvio de requests.CRITICAL: Falha na autenticação AWS ou indisponibilidade total da Gupy.5. Próximos Passos (Critérios de Aceite)Para dar o "check" de finalizado, o programa precisa cumprir os seguintes testes:Executar ponta a ponta sem intervenção manual.Salvar o arquivo no S3 com a estrutura de pastas correta.Não expor chaves de acesso no código (passar em testes de linter/segurança).
